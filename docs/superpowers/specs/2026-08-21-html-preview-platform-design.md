# HTML 原型预览与版本管理平台设计

## 1. 背景与目标

当前项目是一个基于 Flask 的个人作品集网站。产品最初用于上传单个、自包含的 HTML 文件，并将生成的页面链接发送给开发人员查看，从而避免通过聊天工具反复传输文件。

本次升级将产品定位调整为“HTML 原型预览与版本管理平台”。平台保留公开作品展示能力，同时强化项目组织、版本追溯、永久链接、私有权限和历史数据迁移。

第一期目标：

- 管理员可以按项目持续上传单个 HTML 新版本。
- 每个历史版本拥有内容不变的永久链接。
- 每个项目拥有始终指向当前版本的固定链接。
- 开发人员无需注册，获得公开项目链接后即可查看。
- 非公开项目只允许管理员查看。
- 完整迁移 PythonAnywhere 线上已有作品和文件，确保可验证、可回退。
- 使用 Cloudflare 的边缘网络提高 HTML 预览访问速度。

第一期不包含：

- 评论、页面标注和消息通知。
- 团队、多人管理员和复杂角色权限。
- 在线编辑 HTML。
- HTML 源码或视觉差异比较。
- 点赞及其他社交功能。

## 2. 用户与权限

系统包含两类用户：

### 2.1 管理员

管理员登录后可以：

- 创建、编辑、归档、删除和恢复项目。
- 上传新版本、查看全部历史版本、恢复历史版本。
- 查看公开和私有项目及其全部版本。
- 修改项目公开状态。
- 管理封面、分组和项目说明。

第一期只有一个管理员身份，不建设团队体系。

### 2.2 游客

游客无需注册或登录，可以：

- 浏览作品广场中的公开项目。
- 通过公开项目固定链接访问当前版本。
- 通过公开版本永久链接访问指定历史版本。
- 查看公开项目的历史版本列表。

游客访问私有项目或私有版本时，系统返回 HTTP 403，并显示“无权限查看”页面及返回作品广场的入口。页面不得返回 HTML 文件内容。

## 3. 核心概念

### 3.1 项目

一个项目对应一个持续迭代的 HTML 原型或需求。项目包含名称、简介、备注、分组、封面、公开状态和多个版本。

项目具有不可猜测的随机分享 ID。项目固定链接保持不变，默认打开项目的当前版本。

### 3.2 版本

每次上传生成一个不可变版本，版本号在项目内从 V1 开始递增。版本保存更新说明、原始文件名、文件大小、文件哈希、创建时间和 R2 对象位置。

版本永久链接始终返回该版本发布时的 HTML 内容。上传新版本不得覆盖旧版本文件或改变旧版本链接的内容。

### 3.3 当前版本与恢复

正常上传后，新版本成为项目当前版本。项目固定链接始终解析到当前版本。

恢复历史版本不会修改或覆盖任何旧版本。系统复制目标历史版本的文件，并创建一个新的递增版本。例如项目已有 V1 至 V5，恢复 V2 时生成内容与 V2 相同的 V6，V6 成为当前版本，并记录恢复来源。

### 3.4 公开状态

公开状态属于项目，项目下所有版本统一继承：

- 公开：游客可访问项目固定链接、所有版本永久链接和历史版本列表；项目可出现在作品广场。
- 私有：只有管理员可以访问项目及其版本；游客访问时显示“无权限查看”。

项目从公开切换为私有后，现有分享链接立即停止对游客提供内容。重新公开后，原链接恢复可用。

## 4. 系统架构

平台采用以下 Cloudflare 服务：

- Cloudflare Workers：处理页面请求、管理员认证、管理接口、权限判断和分享链接解析。
- Cloudflare D1：保存项目、版本、管理员会话、回收站和审计元数据。
- Cloudflare R2：保存版本 HTML 文件和项目封面。
- Cloudflare 全球网络：向游客分发公开 HTML 内容。

管理后台与上传的 HTML 使用不同主机名或等价的独立安全边界。预览内容不得接触管理后台 Cookie，避免上传 HTML 读取管理员会话。

典型上传流程：

1. 管理员在后台选择项目并上传 HTML。
2. Worker 验证登录状态、CSRF 令牌、文件类型和大小。
3. 系统计算 SHA-256 哈希并将文件写入 R2 的唯一对象键。
4. R2 写入成功后，在 D1 事务中创建版本并更新项目当前版本。
5. 系统返回项目固定链接和版本永久链接。
6. D1 写入失败时，系统删除本次产生的孤立 R2 对象。

典型访问流程：

1. 游客打开项目固定链接或版本永久链接。
2. Worker 根据随机分享 ID 查询 D1。
3. Worker 检查项目存在性和公开状态。
4. 项目公开时从 R2 返回对应 HTML；项目私有时返回 403 页面。

## 5. 数据模型

### 5.1 projects

- `id`：内部主键。
- `share_id`：不可猜测的项目分享 ID，唯一。
- `name`：项目名称。
- `description`：项目简介。
- `remark`：项目备注。
- `group_name`：分组名称。
- `cover_object_key`：R2 封面对象键，可为空。
- `is_public`：公开状态。
- `current_version_id`：当前版本 ID。
- `next_version_number`：下一个版本序号，用于并发安全地生成版本号。
- `status`：`active`、`archived` 或 `trashed`。
- `created_at`、`updated_at`：创建和更新时间。
- `trashed_at`：进入回收站时间，可为空。

### 5.2 versions

- `id`：内部主键。
- `project_id`：所属项目。
- `share_id`：不可猜测的版本分享 ID，唯一。
- `version_number`：项目内递增版本号。
- `change_note`：更新说明。
- `original_filename`：原始文件名。
- `object_key`：R2 HTML 对象键，唯一且不可复用。
- `file_size`：文件字节数。
- `sha256`：文件 SHA-256 哈希。
- `restored_from_version_id`：恢复来源版本，可为空。
- `created_at`：创建时间。
- `deleted_at`：删除时间，可为空。

项目内的 `version_number` 建立唯一约束。分享 ID 使用足够长的密码学安全随机值，不使用递增主键或短 ID。

### 5.3 admin_sessions

- `id`：会话主键。
- `token_hash`：会话令牌哈希。
- `created_at`、`expires_at`：创建和过期时间。
- `last_used_at`：最近使用时间。

管理员密码以 Cloudflare Secret 保存的安全密码哈希或等价安全认证方案管理，不写入仓库、D1 明文或前端代码。

### 5.4 audit_logs

记录登录、项目公开状态切换、上传、恢复、删除、回收站恢复和永久删除等关键操作。审计记录至少包含操作类型、目标、时间和结果。

## 6. 页面与交互

### 6.1 游客页面

作品广场只展示正常状态的公开项目。项目卡片显示封面、名称、简介、分组、当前版本和最近更新时间。

项目固定链接默认打开当前版本，并提供简洁的版本信息栏，包括项目名称、版本号、更新说明、发布时间和历史版本入口。用户可以全屏打开 HTML。

版本永久链接打开指定版本，并明确显示其历史版本号，避免开发人员误认为这是最新版。

404 页面用于不存在或已永久删除的资源。403 页面用于游客访问私有项目或私有版本。

### 6.2 管理后台

管理后台首页按项目展示，不再将每个 HTML 版本平铺为独立作品。每个项目显示：

- 名称、封面和分组。
- 公开或私有状态。
- 当前版本、版本数量和最近更新时间。
- 复制项目链接、上传新版本、编辑、归档和删除操作。

项目详情页显示版本时间线。每个版本显示版本号、原始文件名、文件大小、SHA-256、更新说明、创建时间和恢复来源，并支持管理员预览、复制永久链接和恢复为新版本。

### 6.3 创建项目

管理员填写项目名称、简介、备注、分组、公开状态和可选封面，并上传首个 HTML。全部必要写入成功后创建项目 V1。

### 6.4 上传新版本

管理员从已有项目进入上传页，选择 HTML 并填写更新说明。上传成功后系统生成下一个版本号，将其设为当前版本，并展示两个复制按钮：

- 复制最新版链接。
- 复制本版本链接。

### 6.5 归档、回收站与删除

归档项目不出现在默认管理列表和作品广场中，但数据及管理员访问能力保留。

删除项目时先进入回收站，保留30天。回收站内可以恢复项目或执行永久删除。永久删除清理D1项目和版本记录、R2中的全部HTML及封面。

删除单个历史版本需要二次确认。当前版本不能直接删除，管理员必须先通过上传或恢复产生其他当前版本。第一期不执行无人值守的自动永久删除；后台显示超过30天的项目，由管理员确认清理，避免误删。

## 7. 文件与一致性规则

- 只接受单个 `.html` 或 `.htm` 文件。
- 单文件最大16MB，空文件拒绝上传。
- 服务端不能仅依赖扩展名，必须执行基础内容验证。
- R2对象键由内部项目ID、版本ID和随机值组成，不能由用户文件名直接决定。
- 版本发布后不得覆盖其R2对象。
- 上传请求包含幂等键，重复提交不得生成多个版本。
- 版本号分配、版本创建和当前版本更新必须保证并发一致性。
- 每次上传保存文件大小和SHA-256，用于迁移与日常完整性核验。

## 8. 安全要求

- 管理员密码不以明文保存。
- 管理会话Cookie启用 `HttpOnly`、`Secure` 和适当的 `SameSite` 策略。
- 所有写操作验证管理员身份与CSRF令牌。
- 登录接口提供基础速率限制和失败保护。
- 管理接口不向游客返回私有项目元数据。
- 上传HTML与管理后台隔离，预览响应不携带管理Cookie。
- 预览响应设置适合HTML的安全头；是否允许脚本、表单和网络访问以原型正常运行需求为准，但不得获得管理域权限。
- GitHub仓库不得包含密码、Cloudflare密钥、Cookie、线上数据备份或管理员配置。
- 生产密钥仅通过Cloudflare Secrets配置。

## 9. PythonAnywhere 线上数据迁移

PythonAnywhere 线上目录是迁移的权威数据源。本地仓库中的 `works.json` 和上传目录不能替代线上核对。

迁移流程：

1. 管理员暂停旧站上传，确定迁移时间点。
2. 在PythonAnywhere打包并下载 `data/`、`static/uploads/`、`static/covers/` 和 `static/avatars/`。
3. 单独安全备份 `config.local.json`，不得提交GitHub或导入公开存储。
4. 生成迁移清单，记录作品元数据、文件路径、大小和SHA-256。
5. 每个旧作品转换为一个项目，原HTML作为V1。
6. 保留名称、简介、备注、分组、封面、创建时间和 `is_public` 状态。
7. 将HTML和封面上传R2，将项目和版本元数据写入D1。
8. 对比迁移前后记录数、文件数、大小和SHA-256。
9. 逐项验证公开、私有、管理员访问和HTML渲染。
10. 全部验收完成后再切换正式使用入口。

Cloudflare上线与迁移期间不覆盖或删除PythonAnywhere旧站。迁移完成后保留旧站及离线压缩备份一段观察期，作为回退来源。旧链接不会自动变成Cloudflare链接；如需兼容，另行维护旧站跳转映射。

## 10. 异常处理

- 文件校验、R2写入或D1写入失败时，前端显示明确错误，且不产生半完成版本。
- D1写入失败后尝试清理本次产生的R2孤立对象，并记录审计事件。
- R2对象异常缺失时返回“文件暂时不可用”，不返回空白成功页，并在管理后台标记异常。
- 项目或版本不存在时返回404。
- 私有内容被游客访问时返回403和“无权限查看”。
- 分享链接解析不应泄露内部数据库主键。
- 永久删除需要二次确认，并显示将删除的版本数量与文件总大小。

## 11. 测试与验收

### 11.1 自动化测试

- 权限测试：公开、私有、管理员和游客的访问矩阵。
- 版本测试：递增版本、永久链接不变、项目固定链接切换。
- 恢复测试：恢复历史版本生成新版本且内容哈希一致。
- 上传测试：合法文件、非法扩展名、空文件、超限文件、中断和重复提交。
- 一致性测试：R2成功/D1失败、并发上传和当前版本更新。
- 生命周期测试：归档、回收站、恢复、历史版本删除和永久删除。
- 安全测试：认证、CSRF、Cookie属性、私有元数据泄露和随机ID不可枚举。

### 11.2 上线验收

- 能创建项目并上传V1。
- 能连续上传V2和V3，旧版本链接内容保持不变。
- 项目固定链接正确指向当前版本。
- 恢复旧版本后生成新版本。
- 游客能查看公开项目，访问私有项目时看到403无权限页面。
- 管理员能查看公开和私有项目。
- 归档、回收站、恢复和永久删除符合设计。
- 手机与电脑均可正常查看HTML。
- 线上迁移前后记录数、文件数、文件大小和哈希核验一致。
- GitHub历史与当前文件中不存在账号密码和平台密钥。

## 12. 发布与运维

源代码推送至GitHub，通过Cloudflare官方集成或部署命令发布。生产环境和本地测试环境使用不同的D1数据库、R2存储桶和密钥。

发布顺序：

1. 完成本地实现和自动化测试。
2. 部署Cloudflare测试环境。
3. 使用测试HTML验证全流程。
4. 备份PythonAnywhere线上数据。
5. 小批量迁移并人工核验。
6. 全量迁移并执行自动核对。
7. 用户验收后切换正式入口。
8. 保留PythonAnywhere与离线备份作为观察期回退方案。

GitHub、Cloudflare和PythonAnywhere均通过官方登录或授权页面由用户完成认证，不在对话中传递明文密码。

## 13. 后续候选能力

以下能力不属于第一期，只有在实际使用产生明确需求时再评估：

- 自定义域名与旧链接跳转。
- 项目搜索和更丰富的筛选。
- HTML版本视觉对比。
- 自动清理超过30天的回收站。
- 多管理员、团队和细粒度分享权限。
- 访问统计和链接失效时间。
